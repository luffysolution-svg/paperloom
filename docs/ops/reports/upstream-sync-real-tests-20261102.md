适配差异：

- 上游磁盘查询在非 Unix 平台返回未知；本项目使用 `fs2::available_space`，让 Windows 桌面也能获得实际余量。
- 上游翻译 workers 上限为 256，但本项目既有 DeepSeek 自动并发默认值为 1000。本项目上限保留为 1000，并验证自动默认值兼容；其余参数上限与选定上游修复相同。
- 队列读取只查询任务状态；等待期间任务被删除或取消时退出，并归还取得的名额。建任务和原地重渲染在修改文件前检查资源限制，拒绝时保留旧 PDF。
- 数据库升级快照复用 WAL 安全的 `VACUUM INTO`，也备份 `user_version=0` 但已有业务表的老库；不会把空新库当旧库备份。快照只含数据库，完整文件迁移继续使用上一轮 ZIP 功能。
- 上游 `25068c9c8` 的启动清理迁移化、请求日志、停机/SSE 和缓存回收等尚未同步，本次没有宣称完成整份候选清单。

## 真实测试发现并修复的问题

一页真实 OCR 测试中，MinerU 已完成解析，但本机 DNS 将官方下载域名解析到代理虚拟地址 `198.18.0.105`，下载出现 `tls handshake eof`。使用公共 DNS 返回的官方 CDN 地址，保持原域名/SNI和证书校验，下载可成功。现有恢复分支仅覆盖过期证书，因此新增 TLS EOF 的受限匹配与回归测试；只对 `https://cdn-mineru.openxlab.org.cn:443` 生效，不放宽证书验证，也不对任意下载域名使用该恢复方式。

使用原 MinerU 回执继续流程，没有重新申请 OCR。实际模型完成 13 个文本块的翻译后生成一页中文 PDF；本地开发测试启动时补齐了桌面包自带 Typst 的路径，从渲染阶段续跑，无需重复 OCR/翻译。
