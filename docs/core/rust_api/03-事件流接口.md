## 接口地址

主任务事件流：

`GET /api/v1/jobs/{job_id}/events?start=tail&limit=50`

OCR 子任务事件流：

`GET /api/v1/ocr/jobs/{job_id}/events?start=tail&limit=50`

返回包装固定为：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "protocol_version": 2,
    "items": [],
    "limit": 50,
    "next_cursor": "<opaque cursor>",
    "has_more": false
  }
}
```

前端读取路径是 `data.items`，不是顶层 `items`。
完整历史用 `start=head`；后续原样传 `cursor=data.next_cursor`，不要使用 `offset`
或自行从 `seq` 构造游标。410 `EVENT_CURSOR_EXPIRED` 时重建该任务事件窗口。
API 与第一方客户端必须一起升级。

## 当前口径

`/events` 返回的是 Rust canonical event：

- `event_id`：稳定去重身份；`seq` 仅用于投递顺序。
- `display_stage`：公共阶段，面向前端展示；`stage` 保留来源阶段。
- `substage`：机器可读子阶段。
- `lane`：`main | background | artifact | diagnostic`。
- `event_type`：`progress | artifact | terminal | error | diagnostic`。
- `progress`：公共进度对象。
- `message`：人类可读日志，不能作为机器判断依据。

旧文档中提到的 `progress_current` / `progress_total` / `progress_unit` 是内部来源字段。新前端优先读 `progress`。
