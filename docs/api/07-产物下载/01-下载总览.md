# 下载总览

## 产物接口

```http
GET /api/v1/jobs/{job_id}/artifacts
GET /api/v1/jobs/{job_id}/artifacts-manifest
GET /api/v1/jobs/{job_id}/artifacts/{artifact_key}
```

前端应优先使用 artifact manifest 暴露的 key 和 URL，不直接拼文件路径。

## PDF

```http
GET /api/v1/jobs/{job_id}/pdf
GET /api/v1/jobs/{job_id}/pdf/side-by-side
```

- `/pdf`: 翻译后 PDF。
- `/pdf/side-by-side`: 原文和译文左右对照合成 PDF。

## 图片和预览

```http
GET /api/v1/jobs/{job_id}/cover
GET /api/v1/jobs/{job_id}/thumbnail
GET /api/v1/jobs/{job_id}/preview/pages/{page}
```

## Markdown

```http
GET /api/v1/jobs/{job_id}/markdown
GET /api/v1/jobs/{job_id}/markdown?raw=true
GET /api/v1/jobs/{job_id}/markdown/document
GET /api/v1/jobs/{job_id}/markdown/images/{path}
```

- `/markdown`: 默认可返回带图片 URL 的文档视图或下载响应。
- `?raw=true`: 返回原始 Markdown 文件流。
- `/markdown/document`: 返回 JSON 结构，适合前端展示和 AI 问答。
- `/markdown/images/{path}`: 获取 Markdown 引用图片。

## Obsidian 笔记包

```http
GET /api/v1/jobs/{job_id}/markdown/export
GET /api/v1/jobs/{job_id}/markdown/export?include_source=false
```

返回 ZIP（解压到 Obsidian 库任意目录即可用），需译文已就绪，否则 404：

- `{name}.md`：译文主笔记。frontmatter 含标题、作者、年份、DOI、`paperloom_document` / `paperloom_job` 与回跳链接 `paperloom`；
  跨栏/跨页段落合并为一段；页眉页脚（含 PaddleOCR 的页眉页脚图片，如期刊 logo）与未翻译的元数据块不输出，参考文献保留。
- `{name}.{源语言}.md`：原文笔记，正文为 OCR 产出的 `md/full.md`（与 Markdown 视图一致）。`include_source=false` 时不生成。
- `{name}.assets/`：按首次出现顺序重命名的图片（`fig-001-p03.png`、`tab-`、`eq-`）与译文 PDF `{name}.zh.pdf`。

正文位于 `%% paperloom:begin body %%` / `%% paperloom:end body %%` 之间（Obsidian 注释），供后续重新导出时只替换受管区块。
受管区块还有：

- `links`：笔记互链、`[在 PaperLoom 中打开]`（Zotero 文献另有 `[在 Zotero 中查看]`）、译文 PDF 嵌入。
  回跳链接默认是桌面端协议 `paperloom://open?job=<job_id>&document=<document_id>`；
  Docker 部署设置 `PAPERLOOM_PUBLIC_BASE_URL`（浏览器访问 PaperLoom 的地址）后改为 `<地址>/reader.html?job_id=<job_id>`。
- `zotero`（仅译文笔记，位于正文之后）：导出时实时读取的 Zotero 批注与子笔记。批注以 callout 引用原文、评论另起一段，
  标题行链接 `zotero://open-pdf/...?page=N&annotation=<key>` 可在 Zotero 中定位；子笔记 HTML 转 Markdown（内嵌图片略去）。
  写入库时若这次读不到 Zotero（未运行 / 未挂载），保留笔记里上次导出的该区块。
`{name}` 规则：作者姓 + 年份 + 标题首词 → 标题 → job id，并去除文件系统与 Obsidian 链接敏感字符。

## 直接写入 Obsidian 库

```http
GET  /api/v1/integrations/obsidian
PUT  /api/v1/integrations/obsidian/settings
POST /api/v1/jobs/{job_id}/obsidian/export
```

- 可写入的库只来自发现结果：桌面端读 Obsidian 的 `obsidian.json`（可用 `PAPERLOOM_OBSIDIAN_CONFIG` 覆盖），
  Docker 读 `PAPERLOOM_OBSIDIAN_VAULTS_DIR` 下的挂载目录；目录内须有 `.obsidian`。
- `GET` 返回 `{ vaults: [{id, name, path, source, available}], settings: {default_vault_id, folder, include_source, folder_by_collection}, ... }`。
- `PUT` 保存默认设置；`folder` 只允许库内普通子目录（拒绝 `..`、绝对路径、隐藏目录）。
- `POST` 请求体 `{ vault_id?, folder?, include_source?, folder_by_collection?, on_conflict?: "ask"|"rename"|"overwrite"|"skip", remember?: true }`，
  缺省字段取默认设置；成功写入后默认记住本次选择。
- 返回 `{ status: "created"|"updated"|"conflict"|"skipped", vault_id, vault_name, note_path, source_note_path, files_written, assets_removed, obsidian_uri }`：
  - 同一文献（frontmatter `paperloom_document` 相同）再次导出 → `updated`：只替换受管区块与受管 frontmatter 键，
    用户的其他键、已有 tags、标记外的内容保留；资源目录只清理本次不再引用、且符合 `fig/tab/eq-NNN` 命名的旧文件。
  - 同名文件属于别的笔记（或受管标记被删）→ `ask` 返回 `conflict` 不写入；`rename` 另存为 `-2`、`-3`…，
    之后的导出会自动更新这篇；`overwrite` 整篇替换。
  - `obsidian_uri` 形如 `obsidian://open?vault=…&file=…`，可直接唤起 Obsidian 打开笔记。
